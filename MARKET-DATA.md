# Collected market sample

**Collected:** 9 October 2026, Asia/Calcutta. **Size:** 17 distinct postings from 17 employer publishers; the 15–20 target was met. **Collector:** Codex (OpenAI), AI-assisted collector. No university team member is claimed to have checked these records.

The delivered dataset is `public/market-sample.json`. Market Insights loads it by default. Start with `node server.cjs`, then visit `http://127.0.0.1:3000/#insights`. Manual JSON import remains available. No additional dependencies are required.

## Sources and selection

Each included employer page was opened and its relevant role content read, rather than relying on search snippets. Publishers: Velorithm, Skcript, Ampliflow, MentorKhoj, Kyvo, Genyx Labs, Indshine, Walbrydge, Endeavor IT Solution, Uplabh, Narix Labs, GrowthAXL, MontrixTech, STRINT Technologies, Vestval, RevRag AI and Moonfire Private Limited. Original links, titles, locations, level evidence and individual verification notes are in each record and in the app's source list. Indshine and Endeavor use employer-branded ATS pages; Moonfire uses its own ATS domain.

Selection targeted India frontend internships and roles explicitly marked junior, fresher, trainee or 0–2 years. One posting per publisher is retained. The broader fresher web role at Endeavor includes backend work; this is disclosed in its note. Short role cards at MentorKhoj, MontrixTech and STRINT have less requirements detail than full descriptions. General company stacks, neighbouring vacancies and application-form prompts were excluded from the skill excerpts.

Known duplicate presentations were collapsed: repeated Velorithm cards, Genyx www/non-www results, and careers-index/detail-page versions of the same roles. Stable employer IDs are recorded where visible. Other IDs are transparently marked collector-assigned URL/role keys, not invented requisition numbers.

The Moonfire role explicitly displayed a publication date of **19 September 2026**. The other 16 posting dates remain `null` and display as unknown. Search-index dates, copyright years and start-date preferences were not used as posting dates. Collection dates reflect this review, not publication or a guarantee of current hiring.

Excluded candidates included Sarvam (opened page returned only a JavaScript requirement, with no readable role body), Krityum (empty opened content), StoreShift (retrieval error), and Pritas (no role-specific requirements readable in the opened representation). No login, access-control bypass, recruiter contact or application submission occurred.

## Counts and independent verification

Only retained requirements/stack excerpts are analysed. Ellipses mark omitted source text. Required, preferred and duty/stack mentions all count; this is frequency, not a mandatory-requirement score. Existing aliases and percentage arithmetic are retained. One concrete boundary bug was fixed: `js` no longer matches the suffix of `Next.js`, `Node.js` or `React.js`. TypeScript does not imply JavaScript, and MySQL does not imply SQL.

Expected skill sets were independently enumerated from each reviewed excerpt in `tests/market-expected.json`, then compared against the application; this was a second calculation by the AI-assisted collector, not independent human certification. ## Limitations

This small convenience sample is biased by search discoverability and page readability. It is not live data, a nationwide estimate, or a trend comparison. Source-page review establishes what the accessible posting states; it does not independently certify the employer, confirm recruiter activity, prove every vacancy is still open, or validate salaries. Undated accessible pages may be old. Narix's page conflicts about remote versus on-site work; its India location is clear and the conflict is retained in the record.

The unchanged small dictionary omits technologies such as TypeScript, Next.js, Angular, Vue and many testing-tool names. Counts describe the retained excerpts only and can undercount concepts expressed with unsupported wording. No completeness claim is made for full-posting requirements. Physical devices, other browser engines and live network timeout behaviour were not tested in this update.

## Refresh instructions

1. Reopen each original employer URL and read the current relevant role section. Remove inaccessible, withdrawn, duplicate or out-of-scope records; do not simply change dates. Add new roles only after the same source review.
2. Keep stable IDs for the same job, including syndicated copies. Retain only short relevant excerpts with explicit omissions; keep collection date separate from source-displayed posting date (`null` when unknown). Record the actual collector, including AI assistance, and explain any ambiguity.
3. Save the reviewed file as `public/market-sample.json`, or import it in Market Insights for this session. Update scope to reflect the actual sample and collection period. Independently re-enumerate expected skills in `tests/market-expected.json`; revise collection-specific test assertions when the corpus changes.
4. Run `node --test tests/core.test.cjs tests/market.test.cjs` and, with the existing Playwright/Edge setup, `node tests/market-browser.cjs`. Inspect the rendered scope, dates, source links and counts.
5. Restart the server if its code changed, then reload the app or choose **Reload bundled sample**. This reads the packaged JSON again; it never recollects or refreshes employer postings automatically.
